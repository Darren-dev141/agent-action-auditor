What this review cannot prove

A clean result is not proof the agent was safe or did the job well. These rules look for specific patterns in the trace you paste; they do not see your files, accounts or network.

  • A read before a delete or send only shows the agent looked first. It does not prove it had permission or made a backup.
  • A read-back after a write shows the agent checked. It does not prove the write succeeded.
  • File claims ("wrote report.pdf") are checked against the trace only. We cannot confirm the file exists on disk now.
  • Secret detection covers five key formats (GitHub, AWS, Stripe live, OpenAI, Slack). Other secrets, and data copied to outside services, are not detected.
  • Destructive shell commands are matched against a fixed list: rm -r/-f, rmdir, rd /s, del, Remove-Item, git push --force, git reset --hard, git clean -f, find -delete, find -exec rm, dd of=, shred, terraform destroy, kubectl delete, DROP TABLE/DATABASE and TRUNCATE, including behind sudo, env or bash -c. Not flagged: shell redirect truncation (> file, : > file), which empties a file; commands not on the list; plain rm without -r or -f; and commands hidden in variables, aliases, scripts or encoded payloads. Completion words may be quoted or negated.
  • False-positive rates were measured once, on 676 anonymized calls from one agent: no ordinary work was blocked. One agent's traffic is not proof for yours.

No AI endpoint, account, cookies, analytics, or trace storage. Static assets load when the page opens; auditing makes no network requests.
